Same-machine developer preview: use the local installation role. Remote collection, inference probes, request comparisons and external notifications are experimental and disabled by default. Existing data is preserved. This unsigned build is not a notarized customer release.

Install · Operate · Recover

Recover local services and access

These checks are local and inspect LLM Monitor only.

"$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor" status
launchctl print "gui/$UID/com.llm-monitor.hub"
launchctl print "gui/$UID/com.llm-monitor.collector"
tail -n 100 "$HOME/Library/Logs/LLM Monitor/hub.error.log"
tail -n 100 "$HOME/Library/Logs/LLM Monitor/collector.error.log"

For an ordinary permission, path or port problem, resolve the reported cause and rerun these checks. If a restore was interrupted, use the recovery inspection below before running setup.

"$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor" install check --role local
"$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor" setup local

Expired first-admin token

"$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor" admin bootstrap-renew

Verify an encrypted backup

Use the private recovery key stored separately from the backup. Verification checks the archive, manifest, database integrity and referenced files before restoration. It does not replace the installed database.

LLM_MONITOR="$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor"
"$LLM_MONITOR" backup verify --from "/absolute/monitor.age" \
  --key-file "/absolute/recovery.key" --confirm-deployment "DEPLOYMENT-UUID" --json

Restore to a reviewed recovery point

Record the current deployment ID and generation from status --json, and the backup recovery point from verification. Stop only the monitor's hub LaunchAgent before restore. The command refuses a running or unknown hub and preserves the displaced state. A backup contains only its recorded recovery point; later changes may be missing even when some collector records remain recoverable.

launchctl bootout "gui/$UID/com.llm-monitor.hub"
"$LLM_MONITOR" restore --from "/absolute/monitor.age" \
  --key-file "/absolute/recovery.key" --confirm-deployment "DEPLOYMENT-UUID" \
  --deployment-generation "CURRENT-GENERATION-UUID" \
  --confirm-recovery-point-ms RECOVERY-POINT-MILLISECONDS --json

Restore changes the collector CA and security generation, invalidates old sessions and tokens, and requires a new administrator. Return to the local browser after the owner command and choose Check again; the one-use setup handoff is obtained automatically and no token file needs to be found. Previously revoked collectors do not reconnect automatically. Explicitly re-enroll reviewed collectors before resuming their monitoring. Retained old spool data is not automatically authorized for replay.

After restore reports completion, load the existing hub LaunchAgent, open the saved local monitor address, and create the new administrator. Then explicitly re-enroll this Mac's retained local collector:

launchctl bootstrap "gui/$UID" "$HOME/Library/LaunchAgents/com.llm-monitor.hub.plist"
# Complete first-administrator setup in the local browser before this command:
"$LLM_MONITOR" setup local --re-enroll

The explicit re-enrollment preserves the local host identity and retained spool files. A remote collector needs a separately reviewed enrollment transfer for its retained host and the new CA fingerprint.

Resume an interrupted restore

Ordinary commands intentionally stop while restore activation is incomplete. This read-only command remains available and reports the verified transaction, recovery point and exact resume_argv:

"$LLM_MONITOR" recovery inspect --json

For a custom installation, pass the same --installation-root and --runtime-dir values used before interruption. Review the reported recovery point and pass the returned argument tokens to the verified executable. Text mode prints an equivalent safely quoted command. Do not run setup, delete the journal or invent a transaction ID. A missing or damaged journal produces no automatic resume instruction; preserve the installation and its recovery directory for inspection.

Resume a partial removal

A partial removal exits with code 6 and returns retry_arguments. Resolve the reported stop, permission, socket-owner or file-removal failure. Then pass those exact argument tokens to the same verified llm-monitor binary. The normal output prints an equivalent safely quoted Retry: command.

VERIFIED_LLM_MONITOR="/path/to/the/same/verified/llm-monitor"
"$VERIFIED_LLM_MONITOR" \
  --installation-root "$HOME" \
  --runtime-dir "$HOME/Library/Caches/LLM Monitor/run" \
  uninstall --keep-data --deployment-generation "GENERATION-UUID"

The authenticated receipt at ~/Library/Application Support/LLM Monitor/removal-receipt.json remains until removal fully succeeds and binds the retry to its deployment ID, generation and mode. Do not run setup or delete the receipt manually between attempts. If the final receipt deletion failed after the installed executable was removed, restage the same already-verified package or use its externally staged binary, then run the returned arguments. Purge retries also include the original --confirm-deployment value and --backup-offer-acknowledged.

Do not kill an unrelated port owner, edit a running database or delete LaunchAgent files manually. Use uninstall --keep-data --preview to enumerate product-owned service files while retaining protected state.
