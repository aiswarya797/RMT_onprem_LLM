Same-machine developer preview: use the local installation role. Remote collection, inference probes, request comparisons and external notifications are experimental and disabled by default. Existing data is preserved. This unsigned build is not a notarized customer release.

Install · Operate · Recover

Operate the local monitor

LLM Monitor reports service state, native host observations and persisted history. Setup creates a safe loopback-only target for bounded read-only Ollama checks. Monitoring does not load a model or send inference requests.

Read each value with its age and quality. Reachable Ollama, installed models, loaded models and observed requests are separate facts. Missing inventory is not an empty model list. No captured requests does not mean there is no inference traffic. During a hub outage, the collector retains bounded history for replay; historical replay does not make current status fresh.

LLM_MONITOR="$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor"
"$LLM_MONITOR" status
"$LLM_MONITOR" status --json
"$LLM_MONITOR" install check --role local|master|collector
"$LLM_MONITOR" stop

First administrator

The one-use setup handoff expires after 30 minutes. The local browser obtains it automatically. If no administrator exists and it has expired, renew it:

"$LLM_MONITOR" admin bootstrap-renew

The browser does not persist the handoff or password in URLs or application browser storage. Sign out to revoke the current session.

Connect another Mac

On a master installation, choose Connect another Mac in the dashboard. It generates one command of this form:

./llm-monitor-install.sh collector --hub-url "https://MASTER-IP:PORT" --pairing-code "PAIRING-CODE"

The dashboard shows Waiting, Connected, Expired or Failed. The collector command obtains and pins the hub CA in its private application directory, completes the existing mTLS enrollment and starts the collector user service. No macOS trust store or remote command is used. The collector checks its own loopback Ollama endpoint; target selection remains collector-side.

CLI sign-in

After creating an administrator, use auth login --username NAME --password-stdin --session-file ABSOLUTE_PATH --json. Supply the password on standard input from a password manager or hidden terminal prompt. Never place it in arguments, shell history or scripts. The command creates a new owner-only session file and does not print its secret.

Use that file with auth token create --session-file ABSOLUTE_PATH --name NAME --expires 24h --output-token-file ABSOLUTE_PATH --deployment-generation GENERATION --idempotency-key UNIQUE_KEY --json. Obtain the generation from status --json. Token commands accept exactly one session file or token file.

auth logout --session-file ABSOLUTE_PATH --json confirms revocation before removing the file. If the hub is unavailable, keep the file and retry. Separately created API tokens remain active until revoked with auth token revoke.

Read history and save an investigation

hosts list and history catalog expose retained scope IDs. Use series query --scope ID --metric host.cpu.busy_ratio --start RFC3339 --end RFC3339 --resolution auto to read observations with their coverage and gaps. Supply --session-file FILE or --token-file FILE and --json. Missing measurements remain unavailable.

An administrator can save a focus window with incidents create --title TITLE --scope-kind host --scope ID --start RFC3339 --end RFC3339 --deployment-generation GENERATION --idempotency-key KEY. The saved evidence includes the preceding baseline and explicit unavailable evidence. A manual investigation does not assert that an alert fired.

Read it with incidents show --id ID. Add a declared note with annotations create --incident ID --declared-time RFC3339 --text NOTE; edit with annotations edit --id ID --expected-revision N --text NOTE. Mutations require the administrator credential, current generation and a unique retry key. Notes retain operator-declared provenance.

incidents update --id ID --expected-revision N --title TITLE, incidents close and incidents reopen change manual workflow metadata while preserving frozen evidence. Reopening cannot restore expired evidence and remains subject to capacity. An exact mutation retry returns its original result; read the incident again to see later changes. List commands return next_cursor; pass it with --cursor ID to continue.

Alert rules and controls

Open Alert rules in the UI. Administrators can create or edit a versioned definition; viewers can inspect it. The CLI offers rules list|show|create|edit|disable. Creation and edits read a complete reviewed --definition-file, including expected_revision (null for creation). Supply current generation, credential and idempotency-key flags for mutations; reuse the exact file and key after an uncertain response.

Alert condition, data quality, acknowledgement and delivery are separate. Use incidents acknowledge --id ID --observed-transition-seq N, incidents mute --id ID --reason TEXT --expires RFC3339 or incidents unmute --id ID. Mutes last at most24 hours. Neither action resolves the observed condition; an in-flight notification may still arrive. Read the incident again after an action because retry receipts preserve their original result.

monitor-health show reports authenticated storage and evaluator health. /healthz is process liveness; /readyz returns503 until storage and evaluator are ready. The Services panel warns about failed or delayed evaluation. Notification destination configuration and actual delivery remain incomplete at this checkpoint; saved rules do not establish delivery success or real-model qualification.

Create an encrypted backup

Choose a private directory owned by your macOS account with permissions 0700. The output paths below must be new. The command can run while monitoring continues; it pins one database snapshot and verifies the encrypted archive before publishing it.

"$LLM_MONITOR" backup create --out "/absolute/private-directory/monitor.age" \
  --key-out "/absolute/private-directory/recovery.key" \
  --confirm-deployment "DEPLOYMENT-UUID" \
  --deployment-generation "CURRENT-GENERATION-UUID" --json

Read the ID and generation from status --json. Keep the recovery key separately from the backup; its contents are never printed. To reuse a private recovery key, replace --key-out with --key-file. Existing backups and keys are not overwritten. Automatic daily rotation is not yet implemented in this development build. The recovery guide covers verification, trust-reset restore and interrupted activation.

Login, logout, sleep and wake

Hub and collector are per-user LaunchAgents. They do not run before login or while the Mac is asleep. After login or wake, run "$LLM_MONITOR" status. LLM Monitor never changes power settings.
