Same-machine developer preview: use the local installation role. Remote collection, inference probes, request comparisons and external notifications are experimental and disabled by default. Existing data is preserved. This unsigned build is not a notarized customer release.

Install · Operate · Recover

Install LLM Monitor

LLM Monitor is a read-only monitor for native Ollama on Apple Silicon Macs. The supported runtime boundary is macOS 14 or newer, subject to qualification for the exact Mac, macOS and Ollama combination. The current compatibility manifest is unverified and there is no customer release yet.

One command per role

Keep the generated helper beside the matching package and checksum list. For a qualified release, keep its detached checksum signature, public key and verifier beside them. Run exactly one role command from that folder:

./llm-monitor-install.sh local
./llm-monitor-install.sh master
./llm-monitor-install.sh collector --hub-url "https://MASTER-IP:PORT" --pairing-code "PAIRING-CODE"

local installs the dashboard, storage and collector together. master installs dashboard and storage with a reviewed private listener for another Mac. collector is the generated command for that other Mac. The helper verifies the package, checks compatibility, installs for the current user, starts the supported user service and opens the dashboard where applicable. No Go, Node, source checkout, manual checksum, configuration, certificate file or token-file path is needed.

A development helper is explicitly unqualified and must not be called a customer release. A qualified release requires the publisher's signing, notarization and independently published trust values.

First administrator

For local or master, open http://127.0.0.1:9443 if the helper could not open it. The browser obtains the one-use setup handoff from the loopback hub automatically. Choose the administrator username and password. They remain in memory for this attempt and are not put in the URL or browser storage.

If the handoff expires before an administrator exists, run this local command and return to the browser:

"$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor" admin bootstrap-renew

The secret is never printed. Choose Check again in the browser.

Connect another Mac

On a master, sign in and choose Connect another Mac. The dashboard generates one complete collector command and shows Waiting, Connected, Expired or Failed. The one-use reservation expires after ten minutes. The collector obtains and pins the hub CA in its private application directory, then uses the existing mTLS enrollment. No macOS trust store or remote command is involved.

On the collector Mac, paste the generated command into Terminal. The collector checks the local read-only Ollama endpoint at 127.0.0.1:11434; target authority stays on the collector Mac.

Check, stop and remove

LLM_MONITOR="$HOME/Library/Application Support/LLM Monitor/bin/llm-monitor"
"$LLM_MONITOR" status
"$LLM_MONITOR" stop
"$LLM_MONITOR" uninstall --keep-data --preview
"$LLM_MONITOR" uninstall --keep-data --deployment-generation "GENERATION-UUID"

stop is repeatable and unloads only LLM Monitor's own user services. Re-running setup preserves data and pairing. Purge requires the current deployment ID and generation and removes only the paths shown by its preview. Ollama, its models, Homebrew and unrelated software are never removed.

Audit a qualified release

Ordinary users use the helper. A publisher or auditor can run the existing verifier with the package, checksum list, detached signature, public key, independently published public-key fingerprint and exact Developer ID Installer identity:

./packaging/macos/verify-release.sh \
  "./LLM-Monitor-0.1.0.pkg" \
  "./LLM-Monitor-0.1.0-SHA256SUMS" \
  "./LLM-Monitor-0.1.0-SHA256SUMS.sig" \
  "./LLM-Monitor-0.1.0-SHA256SUMS.pub.pem" \
  "PUBLISHED-PUBLIC-KEY-SHA256" \
  "Developer ID Installer: Example Corp (TEAMID)"
